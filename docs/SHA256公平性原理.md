# SHA-256 承诺开奖 · 公平性原理

## 一句话总结

**先锁码、后开奖、可验真**——期次发布时开奖码就和随机盐一起用 SHA-256 算出哈希指纹并公示，开奖后公布原文，任何人都能自己算一遍验证没有掉包。

---

## 流程拆解

### ① 期次创建时（投注开始前）
核心系统随机生成 **6 位竞猜码** + **一段 16 字节随机盐**，然后算一道 SHA-256：

```
SHA-256("开奖码|盐") → 承诺哈希
```

生成的哈希对全世界公示，开奖码和盐暂不公开。从这一刻起，**开奖码已经被数学锁死，谁都没法偷偷改**——因为只要改动 6 位数字中的任何一个，最终算出来的哈希就会完全不同。

### ② 投注期间
用户正常选号下注。因为公示的只是哈希而不是开奖码本身，没有任何人能通过哈希反推出开奖码（SHA-256 是单向不可逆的）。此时开奖码对包括管理员在内的所有人都是一个「已知被锁死、但不知道具体值」的秘密。

> **关键设计：为什么加盐？**
> 
> 6 位纯数字只有 100 万种排列（000000 到 999999）。如果有人事先用电脑把 100 万种可能全部预先算一遍 SHA-256，拿到一张「彩虹表」，那他看到公示的哈希就能瞬间翻查出对应的开奖码——完全不用等到开奖。
> 
> 加上一段 16 字节随机盐之后，输入变成 `"数字 | 32位随机hex"`，可能的组合量从「100 万」直接跳升到「2 的 128 次方」这个天文级别——算完宇宙灭尽也算不完。盐就像是把 6 位数的小水坑炸成太平洋，让暴力预先破解彻底不可能。

### ③ 开奖时
系统公布开奖码原文和随机盐。所有人现在手上有了三样东西：公示的承诺哈希、公布的开奖码原文、公布的随机盐。

### ④ 验证环节
任何人用任意 SHA-256 工具（浏览器、命令行、在线工具），把公布的开奖码和盐拼起来，自己算一遍哈希。如果算出来的结果和期次创建时公示的哈希**完全一致**，那就等于用数学证明：开奖码从创建到开奖**没有被掉包**。

```
用户自己算：SHA-256("开奖码|盐") = ?
        如果等于公示哈希 → ✓ 未被篡改
        如果不等于       → ✗ 中间被换过
```

## 防什么、不防什么

| 能保证 | 暂无法保证 |
|---|---|
| 投注截止后，开奖码无法被修改（改了哈希就对不上） | 管理员在期次创建时就知道开奖码（单服务器限制） |
| 开奖后任何人可以独立验证，不依赖信任平台 | 尚未引入去中心化随机源 |
| 公示的哈希和公布的码+盐只要对准，流程就是诚实的 | |

> **升级方向**：后续接入区块链 VRF（可验证随机函数），把随机数生成交给链上合约，实现连管理员都无法预知开奖码的去中心化公平性。

> 我们用 SHA-256 给开奖码拍了一张指纹照，先公开指纹、再开奖。开奖后你把公布的号码自己套进公式算一遍，指纹对上了就是真的——**代码不需要你信，数学逼它诚实。**
